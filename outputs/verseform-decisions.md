# Verseform — Decision Register

Record only durable choices that constrain later work. Change a decision by adding a superseding row; do not rewrite history after implementation depends on it.

| ID | Status | Decision | Reason |
|---|---|---|---|
| `D-001` | Accepted | Ship Windows first; make no macOS, Linux, or web-distribution claim. | Removes platform evidence that does not serve the first release. |
| `D-002` | Accepted | Use Tauri 2, React, TypeScript, and open-source Tiptap/ProseMirror. | Provides a light native shell and mature rich-text semantics without building an editor engine. |
| `D-003` | Accepted | Keep deterministic rules in a pure TypeScript core and privileged OS work in narrow Rust commands. | Makes most behavior fast to test while preserving a small trust boundary. |
| `D-004` | Accepted | Use a versioned `.verseform` JSON envelope and atomic native writes. | The `VFM-010` walking slice round-trips editor JSON and its Windows smoke proves replacement, reopen, and preservation of the last good file after invalid input. |
| `D-005` | Accepted | Store detected references as transient decorations and inserted citations as editable semantic marks. | The `VFM-010` walking slice proves decorations are derived, citations survive reopen, remain editable, and are excluded from detection. |
| `D-006` | Accepted | Run most end-to-end behavior in a browser harness with fake ports; run Windows evidence only for native claims and gates. | Minimizes slow, fragile, and expensive verification without weakening platform-specific claims. |
| `D-007` | Accepted | Bundle WEB for offline use; do not persistently cache other passage text without permission. | Guarantees offline behavior while respecting translation licensing. |
| `D-008` | Accepted; refined by `VFM-050` | Render one immutable output snapshot behind an adapter; send Print to the WebView2 system print UI and send Save PDF to `PrintToPdf` only after a dedicated native Save dialog grants the destination. | The three-page Edge acceptance PDF has extracted and visually inspected proof of complete content, per-page DBS footer/notices, faithful formatting, and optional numbering. Browser and native cases cover cancellation, bad destinations, offline output, and path confinement. |
| `D-009` | Pending DBS input | Select the production desktop authorization mechanism and exact DBS contract. | A shared secret embedded in a distributed binary is recoverable and cannot be treated as confidential. |
| `D-010` | Pending DBS input | Source canon bounds and attribution rules per translation from DBS when available. | Validation and legal output must match the actual authorized translation. |
| `D-011` | Accepted | Keep native file dialogs and file access inside dedicated Rust commands; allow subsequent writes only to paths granted by the current dialog session or the local recent-file profile. | `VFM-020` provides native Open/Save/Save As without broad frontend filesystem permission, while recovery after restart can safely resume a known recent document. |
| `D-012` | Accepted | Make canon metadata an injected translation contract and bundle a versioned 66-book WEB canon for offline detection; replace its per-translation bounds with authoritative DBS metadata when `D-010` is resolved. | `VFM-030` keeps detection local and deterministic while proving that the same reference can validate differently under another translation's versification. |
| `D-013` | Accepted; supersedes the cache restriction in `D-007` | Persist successful DBS catalogs for 24 hours and chapters for 7 days; cap the app-local chapter cache at 32 MB/192 files and every catalog response at 8 MB; keep bundled WEB as the explicit offline default. | The owner confirmed DBS permission to cache verses. Bounded caching reduces repeat traffic without uploading document content or mislabeling fallback text. |
| `D-014` | Accepted; resolves `D-009` | Use the public, unauthenticated `https://arc.dbs.org/api/bible-text/` JSON catalog and chapter endpoints through an allowlisted native HTTPS adapter. Do not embed a shared secret, load the inScript remote detector, or render provider HTML. | The official ARC API is documented as free for developers and researchers, and a live no-secret smoke confirms the current catalog and passage contract. Native access preserves the restrictive webview CSP and bounds redirects, time, size, schema, and cache paths. |
| `D-015` | Accepted; resolves `D-010` and supersedes the replacement clause in `D-012` | Carry DBS catalog title/copyright metadata into every citation and output notice. Use the bundled WEB main-text profile for WEB and the standard 66-book profile for DBS detection; treat a provider-confirmed chapter as final authority for edition-specific omissions. | ARC exposes translation identity and copyright but not a complete per-edition verse-bound manifest. This keeps detection local while preventing unavailable provider text from being inserted or cited under another translation. |
| `D-016` | Accepted | Package the Windows alpha as a current-user x64 NSIS installer, use the WebView2 download bootstrapper only when the runtime is absent, and keep the alpha unsigned until a trusted signing identity is provisioned. Restrict the webview to one local-only main-window capability and a CSP with no remote origins. | Local and clean-runner lifecycle proof covers install, provider-blocked launch, registration, user-document preservation, and uninstall; the explicit unsigned limit is safer than implying publisher trust that the alpha does not yet have. |
| `D-017` | Accepted | Honor an explicit saved translation first; otherwise prefer a catalog translation identified as NASB for the first online session, then WEB, then the first available catalog entry. A temporary WEB fallback never replaces the saved preference. | Matches the owner-selected writing default while preserving user choice and reliable offline behavior without hardcoding one provider-specific NASB identifier. |
| `D-018` | Accepted | Refactor Alpha orchestration behind one framework-free application kernel: a canonical regional workspace state, closed event/effect unions, pure transitions and selectors, and a controller that alone executes effects through injected ports. Derive dirty/title/enablement facts instead of mirroring them in React state and refs. | The main remaining comprehension and correctness cost is not the core or adapters but cross-cutting lifecycle logic concentrated in `App.tsx`. One control plane makes async ownership, failure behavior, and user-visible state cheap to inspect and prove without introducing a state-management framework. |
| `D-019` | Accepted | Put application commands behind one finite registry and Tiptap behind a narrow editor gateway. Permit a redacted, read-only diagnostic snapshot only in the browser harness; never ship it as telemetry, persistence, dynamic registration, or remote control. | Menus, shortcuts, editor observations, and orchestration tests need shared semantics. These boundaries let an agent trace intent to effect to visible result with fewer full UI/native runs while keeping production authority and document data constrained. |
| `D-020` | Accepted | For Beta, make the writing surface visually primary: keep Verseform identity in the native title rather than a duplicate visible page heading, tighten the existing flat controls through shared tokens, and add Help → Credits & Licenses. Credit DBS and expose translation/WEB/software notices locally; open only allowlisted external links outside the privileged webview and never imply DBS endorsement. | Daily writing benefits from less chrome and predictable grouping, while an explicit local credits surface honors the scripture provider and makes licensing legible without weakening CSP or attribution rules. |
