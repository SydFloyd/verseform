# Verseform — Decision Register

Record only durable choices that constrain later work. Change a decision by adding a superseding row; do not rewrite history after implementation depends on it.

| ID | Status | Decision | Reason |
|---|---|---|---|
| `D-001` | Accepted | Ship Windows first; make no macOS, Linux, or web-distribution claim. | Removes platform evidence that does not serve the first release. |
| `D-002` | Accepted | Use Tauri 2, React, TypeScript, and open-source Tiptap/ProseMirror. | Provides a light native shell and mature rich-text semantics without building an editor engine. |
| `D-003` | Accepted | Keep deterministic rules in a pure TypeScript core and privileged OS work in narrow Rust commands. | Makes most behavior fast to test while preserving a small trust boundary. |
| `D-004` | Accepted | Use a versioned `.verseform` JSON envelope and atomic native writes. | The `VFM-010` walking slice round-trips editor JSON and its Windows smoke proves replacement, reopen, and preservation of the last good file after invalid input. |
| `D-005` | Accepted | Store detected references as transient decorations and inserted citations as editable semantic marks. | The `VFM-010` walking slice proves decorations are derived, citations survive reopen, remain editable, and are excluded from detection. |
| `D-006` | Accepted | Run most end-to-end behavior in a browser harness with fake ports; run Windows evidence only for native claims and gates. | Minimizes slow, fragile, and expensive verification without weakening platform-specific claims. |
| `D-007` | Accepted | Bundle WEB for offline use; do not persistently cache other passage text without permission. | Guarantees offline behavior while respecting translation licensing. |
| `D-008` | Accepted; refined by `VFM-050` and superseded in part by `D-021` | Render one immutable output snapshot behind an adapter; send Print to a WebView2 print UI and send Save PDF to `PrintToPdf` only after a dedicated native Save dialog grants the destination. | The three-page Edge acceptance PDF has extracted and visually inspected proof of complete content, per-page DBS footer/notices, faithful formatting, and optional numbering. Browser and native cases cover cancellation, bad destinations, offline output, and path confinement. |
| `D-009` | Pending DBS input | Select the production desktop authorization mechanism and exact DBS contract. | A shared secret embedded in a distributed binary is recoverable and cannot be treated as confidential. |
| `D-010` | Pending DBS input | Source canon bounds and attribution rules per translation from DBS when available. | Validation and legal output must match the actual authorized translation. |
| `D-011` | Accepted | Keep native file dialogs and file access inside dedicated Rust commands; allow subsequent writes only to paths granted by the current dialog session or the local recent-file profile. | `VFM-020` provides native Open/Save/Save As without broad frontend filesystem permission, while recovery after restart can safely resume a known recent document. |
| `D-012` | Accepted | Make canon metadata an injected translation contract and bundle a versioned 66-book WEB canon for offline detection; replace its per-translation bounds with authoritative DBS metadata when `D-010` is resolved. | `VFM-030` keeps detection local and deterministic while proving that the same reference can validate differently under another translation's versification. |
| `D-013` | Accepted; supersedes the cache restriction in `D-007` | Persist successful DBS catalogs for 24 hours and chapters for 7 days; cap the app-local chapter cache at 32 MB/192 files and every catalog response at 8 MB; keep bundled WEB as the explicit offline default. | The owner confirmed DBS permission to cache verses. Bounded caching reduces repeat traffic without uploading document content or mislabeling fallback text. |
| `D-014` | Accepted; resolves `D-009` | Use the public, unauthenticated `https://arc.dbs.org/api/bible-text/` JSON catalog and chapter endpoints through an allowlisted native HTTPS adapter. Do not embed a shared secret, load the inScript remote detector, or render provider HTML. | The official ARC API is documented as free for developers and researchers, and a live no-secret smoke confirms the current catalog and passage contract. Native access preserves the restrictive webview CSP and bounds redirects, time, size, schema, and cache paths. |
| `D-015` | Accepted; resolves `D-010` and supersedes the replacement clause in `D-012` | Carry DBS catalog title/copyright metadata into every citation and output notice. Use the bundled WEB main-text profile for WEB and the standard 66-book profile for DBS detection; treat a provider-confirmed chapter as final authority for edition-specific omissions. | ARC exposes translation identity and copyright but not a complete per-edition verse-bound manifest. This keeps detection local while preventing unavailable provider text from being inserted or cited under another translation. |
| `D-016` | Accepted | Package the Windows alpha as a current-user x64 NSIS installer, use the WebView2 download bootstrapper only when the runtime is absent, and keep the alpha unsigned until a trusted signing identity is provisioned. Restrict the webview to one local-only main-window capability and a CSP with no remote origins. | Local and clean-runner lifecycle proof covers install, provider-blocked launch, registration, user-document preservation, and uninstall; the explicit unsigned limit is safer than implying publisher trust that the alpha does not yet have. |
| `D-017` | Accepted | Honor an explicit saved translation first; otherwise prefer a catalog translation identified as NASB for the first online session, then WEB, then the first available catalog entry. A temporary WEB fallback never replaces the saved preference. | Matches the owner-selected writing default while preserving user choice and reliable offline behavior without hardcoding one provider-specific NASB identifier. |
| `D-018` | Accepted | Refactor Alpha orchestration behind one framework-free application kernel: a canonical regional workspace state, closed event/effect unions, pure transitions and selectors, and a controller that alone executes effects through injected ports. Derive dirty/title/enablement facts instead of mirroring them in React state and refs. | The main remaining comprehension and correctness cost is not the core or adapters but cross-cutting lifecycle logic concentrated in `App.tsx`. One control plane makes async ownership, failure behavior, and user-visible state cheap to inspect and prove without introducing a state-management framework. |
| `D-019` | Accepted | Put application commands behind one finite registry and Tiptap behind a narrow editor gateway. Permit a redacted, read-only diagnostic snapshot only in the browser harness; never ship it as telemetry, persistence, dynamic registration, or remote control. | Menus, shortcuts, editor observations, and orchestration tests need shared semantics. These boundaries let an agent trace intent to effect to visible result with fewer full UI/native runs while keeping production authority and document data constrained. |
| `D-020` | Accepted | For Beta, make the writing surface visually primary: keep Verseform identity in the native title rather than a duplicate visible page heading, tighten the existing flat controls through shared tokens, and add Help → Credits & Licenses. Credit DBS and expose translation/WEB/software notices locally; open only allowlisted external links outside the privileged webview and never imply DBS endorsement. | Daily writing benefits from less chrome and predictable grouping, while an explicit local credits surface honors the scripture provider and makes licensing legible without weakening CSP or attribution rules. |
| `D-021` | Accepted; supersedes the system-print-UI clause in `D-008` | Remove the below-editor output preview. Print uses WebView2's browser print-preview dialog; Save PDF uses a dedicated modal Verseform preview with page-number control, Cancel, and Export PDF before the native destination dialog. Keep the live editor as a continuous writing surface rather than adding editing-view pagination. | Microsoft exposes browser preview and system-dialog modes separately. Reusing one immutable output renderer gives both workflows accurate output without coupling content editing, page breaking, printer settings, and footer attribution into one fragile surface. The owner approved this split explicitly during `VFM-110`. |
| `D-022` | Accepted | Ship the Windows Beta as version `0.2.0` through the existing `com.verseform.editor` identity and per-user NSIS upgrade path. Preserve `.verseform` documents and app-local profile, recovery, and scripture-cache data across upgrade and uninstall; keep the installer explicitly unsigned until a trusted signing identity exists. | A stable application identity is the compatibility boundary for Alpha data. The release workflow reuses the retained `0.1.0` artifact on a clean Windows runner, hashes every seeded data class before and after the `0.2.0` upgrade and launch, and proves that uninstall removes the program without treating user data as disposable. |
| `D-023` | Accepted | Operate `0.2.0` as a public GitHub pre-release using the exact clean-runner installer, checksum, and evidence. Keep this field Beta transparently unsigned, treat published version assets as immutable, and collect only optional user-authored feedback through a privacy-constrained public issue form; defer any stable-release or signing claim to a later explicit gate. | The verified Actions artifact expires and is inconvenient for ordinary users, while silently rebuilding or replacing a release asset would break provenance. A durable pre-release makes the tested binary accessible without adding telemetry, accounts, updater authority, or an unsupported publisher claim. |
| `D-024` | Accepted | Pin and bundle Paged.js behind the output-surface boundary to generate one fixed Letter page tree for both review and WebView2 print/PDF. Insert escaped attribution and optional numbering into each generated page, measure the reserved footer, and stamp pagination readiness by output operation and layout version. | Sharing only snapshot content left review and export with different page-breaking engines. One generated page tree makes page boundaries and repeated attribution comparable while keeping pagination out of the editor and preventing stale or overflowing layouts from reaching native output. |
| `D-025` | Accepted | Preserve the exact verified unsigned Alpha installer as a non-latest `v0.1.0` archival pre-release with a committed provenance/integrity manifest. Build the corrected field candidate as `0.2.1`; every clean patch gate must download and hash the durable Alpha release, and successful publication must project the exact clean-runner installer/checksum/evidence into a new immutable pre-release. | The original Actions-only Alpha artifact expires on 2026-09-17 and cannot remain a repeatable upgrade boundary. A separate archival release preserves those exact bytes without presenting Alpha as the current download, while a new patch version honors the immutability of published `0.2.0` assets. |
| `D-026` | Accepted | Deliver the session-blocker corrections as `0.2.2` without folding in the proposed custom-title-bar/menu redesign. Browser unload protects only the browser composition; Windows X-close is owned solely by the native close request and the kernel's Save/Discard/Cancel gate. Permit the force-destroy command only for the local main Windows window, and report a rejected destroy without clearing dirty writing. | Public `0.2.1` is immutable and can strand a later shifted reference or a dirty WebView2 window. A narrow patch restores the two core tasks with focused regressions and the least Tauri authority needed to complete an authorized close, while custom Windows chrome would add drag, window-control, DPI, and accessibility risk unrelated to retesting those blockers. |
| `D-027` | Accepted | Validate complete scripture expressions locally; support whole chapters, ordered verse lists, and same-book cross-chapter ranges. Allow any selection within one chapter, or at most 50 selected verses when crossing chapters. Providers must return the entire selection under one translation or fail; never truncate to fit. | The owner approved correcting partial recognition and documenting a one-chapter-or-50-verses volume limit. Optional reference metadata extends existing citation marks without changing the document envelope or the kernel's stamped, single-transaction insertion path. |
| `D-028` | Accepted 2026-09-07; extends D-001 after Windows publication | Deliver the browser edition from the same repository and shared editor/core through an explicit Vite production entry point for Vercel. Desktop Chrome/Edge use transactional local drafts with tab revision checks, validated import, portable download, bounded anonymous DBS requests, and browser Print/Save PDF. Cache app/WEB after first load; updates wait for tabs to close. Windows publication requires explicit workflow dispatch. | The owner authorized a usable browser instance with local storage and an installer link. Separate production adapters and release triggers preserve real behavior, document safety, and immutable Windows releases without accounts, cloud writing storage, remote rendering, mobile support, or test diagnostics. |
| `D-029` | Accepted 2026-09-07 | For ordinary paragraphs, make Tab adjust a serialized first-line indent while Shift+Tab retains full-paragraph outdent; keep list nesting and dedicated full-paragraph toolbar commands. Move the browser download and usage guidance into File and Help, and make checkbox, translation, and paragraph-indent affordances visually explicit. | Owner testing found the duplicate top actions noisy, the collapsed selector and page-number checkbox unclear, and the shared Tab/full-indent behavior unlike familiar writing tools. A block attribute preserves first-line layout in documents and output without introducing page-wide tab stops or a second editor. |
| `D-030` | Accepted 2026-09-07 | Keep standard USFM book IDs in the local canon and ARC chapter URL, and map all 66 to DBS's two-character IDs when validating returned verse keys. Parse those keys against the exact mapped book and requested chapter rather than inferring their split from a generic regular expression. | Live ARC evidence shows asymmetric identifiers: `/JOB/21` returns `JB21.*`, and `/2PE/3` returns `P23.*`; using `JB` or `P2` in the URL returns an empty chapter. The old generic parser made trailing-number response IDs ambiguous. One shared response mapping fixes web and desktop without weakening local detection or transport validation. |
